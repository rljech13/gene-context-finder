# Ускорение и упрощение Gene Context Finder

Аудит 11 ноября 2026. Это проект изменений, а не описание уже реализованных
ускорений. Работающие задания и исходники вычислений в ходе аудита не менялись.

## Реализация первого шага

Версия 0.10.0 зафиксирована коммитом `d8ec201` и опубликована в `main`.
Пакет проверен установкой в чистый каталог; исходный набор из 189 тестов прошёл
с 24 пропусками инструментальных/необязательных проверок.

В 0.10.1 добавлен общий кэш поисковых баз BLAST и распакованного FASTA/faidx
для основного этапа 1. Ключ включает содержимое входа, тип базы, инструмент и
реализацию подготовки; публикация атомарна, параллельные запросы используют
блокировку. Проверки SHA-256 сохранены. Холодный/повторный поиск проверяются
на точное совпадение локусов и исходных BLAST/HSP-таблиц.

Этот шаг не реализует остальные предложения ниже: индекс GFF, продолжение
произвольного задания, кэш предсказаний Tiberius и разделение интерфейса/данных
остаются следующими этапами. Запущенные серверные расчёты используют прежние
неизменяемые снимки кода.

## Публикация

При первоначальном аудите удалённая `main` была проверена через `git ls-remote`: `401698635e1b9612d318ef7634f6f47e07bebed5`,
6 ноября, версия 0.7.8. Локальная версия — 0.10.0. На момент проверки: 19 изменённых
отслеживаемых файлов и 72 неотслеживаемых; среди последних находятся этапы 2 и 3.
Следовательно, клонирование GitHub сейчас не воспроизводит используемый полный
маршрут. Этот документ не был включён в приведённый счётчик.

Первое действие по выпуску: собрать отдельный проверяемый коммит текущего
маршрута, добавить исходники и шаблоны этапов 2/3, проверить сборку wheel и его
содержимое в чистом каталоге. Сохранить принятый вид NANOG как контрольный пример.
Ускорения вносить следующими коммитами с собственными измерениями.

## Понятный маршрут для пользователя

**Подготовить данные один раз → найти локусы → выбрать локусы (STOP 1) →
проверить модели → выбрать модели (STOP 2) → получить сравнение и FASTA.**

1. Проект содержит список генов, сборок и параметры. У каждого гена собственные
   результаты и решения, общий кэш обслуживает все гены.
2. Подготовка проверяет источники, строит FASTA/GFF/BLAST-индексы, готовит модели
   и справочную базу. Пользователь видит состояние готовности каждого набора.
3. Поиск использует BLASTP по полной доступной аннотации; геномный поиск
   сохраняется для неаннотированных сборок и явно запрошенного поиска пропусков.
   Отсутствие annotation-hit не выдаётся за отсутствие гена.
4. STOP 1 показывает вид, локус, поддержку последовательностью, окружение и
   причину неопределённости. Основное действие — выбрать локусы и продолжить.
5. Проверка моделей извлекает выбранные окна, сохраняет аннотацию, независимо
   запускает Tiberius и идентифицирует белки. Предсказание не подменяет исходную
   аннотацию. Режим пропуска Tiberius был бы отдельным изменением метода и здесь
   не предлагается как незаметная оптимизация.
6. STOP 2 показывает краткую карту и явные варианты CDS/белка. Полные имена,
   доказательства и диагностические сообщения раскрываются по запросу.
7. Итог содержит выбранные последовательности, альтернативы, выравнивания,
   identity вместе с покрытием и неопределённые случаи. Паралоги сохраняют
   отдельные идентификаторы. Сходство не становится автоматически ортологией.

Команды подготовки окружения остаются в разделе обслуживания. На основной
странице проекта достаточно трёх действий: «Найти», «Проверить модели»,
«Сравнить». При каждом действии показываются состояние, использованный кэш,
следующий шаг и конкретная причина ошибки. Переходы между этапами следуют
сохранённым решениям; технические файлы не нужно вручную перекладывать.

## Лёгкая внутренняя структура

- Один небольшой диспетчер задач с общим бюджетом CPU/RAM/I/O, а не независимые
  вложенные множители panels × jobs × threads. Текущий запуск использует
  2 × 4 × 8 = 64 запрошенных BLAST-потока; это не измеренная загрузка CPU.
- Общий `cache` содержит подготовленные наборы, индексы и предсказания.
  Результаты поиска, модели, решения и представления имеют отдельные версии.
- Контроль целостности относится к данным и решениям; CSS и подписи карты
  обновляются без повторного расчёта и смены научного checkpoint.
- Все тяжёлые шаги сохраняют свой результат атомарно. Повторный запуск
  продолжает только незавершённые задачи и проверяет ключи кэша.
- Один поддерживаемый маршрут `stage1 → stage2 → stage3`; прежние команды
  остаются совместимыми оболочками, затем могут быть объявлены устаревшими.

Не требуется сразу вводить workflow-фреймворк, очередь сообщений или серверную
БД. Подходят существующий Python CLI, небольшой манифест проекта, файловый кэш
и SQLite-индексы там, где нужны выборки по координатам.

## Очерёдность реализации и приёмка

1. Зафиксировать используемый код и принятый отчёт в Git; проверить установку.
2. Ввести общие поисковые базы и индексы. Контроль: второе задание другого гена
   повторно использует их; исходные locus/model IDs, координаты и наборы кандидатов
   не меняются. Совпадение BLAST-статистик проверить на сохранённых контролях.
3. Добавить продолжение задач и кэш предсказаний. Затем измерить загрузку
   TensorFlow/весов и инференс раздельно. Предложенный пул работников принимается
   только после проверки изоляции окон: добавление более длинного несвязанного
   окна не должно менять предсказание исходного окна.
4. Отделить представление от вычислений; сохранить старый NANOG как визуальный
   контроль. Проверять реальные узкую и широкую панели, а не только DOM/формулы.
5. Добавить единый обзор проекта и переходы между двумя ручными остановками.

Время и память измерять отдельно для холодного/тёплого кэша, одного/нескольких
генов и самого крупного входа. Прогноз кратности ускорения пока не измерен.
